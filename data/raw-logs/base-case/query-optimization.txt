# Query Optimization Strategies

## Configuration Setup

### Enable Slow Query Logging
**Commands:**
```sql
ALTER SYSTEM SET log_min_duration_statement = 1000; -- Log queries taking > 1 second
SELECT pg_reload_conf();
```

**Purpose:** Track and analyze queries that take longer than 1 second to execute.

---

## Query Analysis with pg_stat_statements

### What is pg_stat_statements?
The `pg_stat_statements` extension is a powerful tool for PostgreSQL query performance analysis.

**Key Features:**
- 📊 Tracks execution statistics for all SQL statements
- ⏱️ Measures cumulative execution time
- 📈 Counts query execution frequency
- 💾 Monitors buffer cache performance
- 🎯 Identifies resource-intensive queries

### Query Analysis Query
```sql
SELECT query, calls, total_exec_time, rows, 
       (shared_blks_hit * 100.0 / (shared_blks_hit + shared_blks_read)) AS hit_percent
FROM pg_stat_statements 
ORDER BY total_exec_time DESC 
LIMIT 10;
```

**What This Shows:**
| Column | Description | Optimization Value |
|--------|-------------|-------------------|
| **query** | SQL statement text | Identify problematic queries |
| **calls** | Number of executions | Find frequently run queries |
| **total_exec_time** | Cumulative execution time | Spot time-consuming operations |
| **rows** | Total rows returned | Understand data volume |
| **hit_percent** | Buffer cache hit ratio | Measure memory efficiency |

## Detailed Query Execution Analysis

### EXPLAIN Command Usage
**Command:**
```sql
EXPLAIN (ANALYZE, BUFFERS, TIMING) SELECT * FROM pgbench_accounts WHERE aid = 12345;
```

### What Each Option Provides:

#### 🔍 ANALYZE
- **Purpose:** Executes the query and provides actual performance metrics
- **Benefits:** Real execution times vs. estimated costs
- **Use Case:** Understanding actual vs. planned performance

#### 💾 BUFFERS  
- **Purpose:** Shows buffer usage statistics
- **Metrics:** 
  - `shared hit` - Data found in memory
  - `shared read` - Data read from disk
  - `dirtied` - Modified buffer pages
- **Use Case:** Memory vs. disk I/O analysis

#### ⏱️ TIMING
- **Purpose:** Provides detailed timing information
- **Metrics:**
  - Planning time
  - Execution time per node
  - I/O timing breakdown
- **Use Case:** Identifying bottlenecks in execution

## Performance Optimization Workflow

### 1. Identify Slow Queries
```sql
-- Find queries taking > 1 second
SELECT query, calls, total_exec_time, mean_exec_time
FROM pg_stat_statements 
WHERE mean_exec_time > 1000
ORDER BY total_exec_time DESC;
```

### 2. Analyze Execution Plans
```sql
-- Get detailed execution plan
EXPLAIN (ANALYZE, BUFFERS, TIMING) 
SELECT * FROM table_name WHERE condition;
```

### 3. Check Index Usage
```sql
-- Monitor index efficiency
SELECT schemaname, tablename, indexname, idx_scan, idx_tup_read, idx_tup_fetch
FROM pg_stat_user_indexes
ORDER BY idx_scan DESC;
```

### 4. Monitor Cache Performance
```sql
-- Check buffer cache hit ratio
SELECT datname, 
       blks_read, 
       blks_hit,
       round((blks_hit * 100.0) / (blks_hit + blks_read), 2) AS hit_ratio
FROM pg_stat_database
WHERE datname = current_database();
```

## 🎯 Optimization Strategy Framework

### High-Impact Optimizations
1. **Index Creation** - For frequently queried columns
2. **Query Rewriting** - Eliminate unnecessary operations  
3. **Buffer Tuning** - Optimize memory allocation
4. **Connection Pooling** - Reduce connection overhead

### Performance Monitoring Checklist
- [ ] Enable `pg_stat_statements` extension
- [ ] Set appropriate `log_min_duration_statement`
- [ ] Monitor index usage statistics
- [ ] Track buffer cache hit ratios
- [ ] Analyze query execution plans regularly

### Key Performance Indicators
| Metric | Target | Action If Below Target |
|--------|--------|----------------------|
| **Buffer Hit Ratio** | >95% | Increase shared_buffers |
| **Index Usage** | >80% of queries | Create missing indexes |
| **Query Execution Time** | <100ms average | Optimize slow queries |
| **Connection Time** | <50ms | Implement connection pooling |

**💡 Critical Insight:**
The combination of `EXPLAIN (ANALYZE, BUFFERS, TIMING)` provides the most comprehensive view of query performance, revealing exactly where optimization efforts should be focused for maximum impact.
